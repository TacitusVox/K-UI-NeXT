The launcher's preflight on original boot programs, with K-UI's memory limit: K-UI aaaba0ea3640 against 53a33ec708ab
====================================================================================================================

Production code: native_cache_prepare_repeat (src/apps/games_native_cache.inc) of commit aaaba0ea, through the
repository's fixture I/O, on the 426 boot programs of the owner's CD-audio archives (kept outside the repository;
no game byte is recorded here). Module: the owner's New reader module of 26 November 2026 (Test 84's
retail-native-dual.kui, build 4abc63b0cc58, payload CRC32 BAFAAF7C). Both Background readers and both Virtual VMU
settings: 1,704 launches a run. The whole-program allocation is refused above a byte limit (the launcher's
KUI_NATIVE_CACHE_BOOT_ALLOC stand-in), as the console refuses it.

Each launch is compared with the same launch under commit 53a33ec7 (docs/evidence/kui-large-program-53a33ec/
corpus-large.txt): size, how the program was held, the number of reads and the CRC result must be equal. A launch
53a33ec7 read in pieces and left without an answer ("skipped": started unchecked) must now be "unchecked", with
the refusal "This game's program is too large for the Background reader yet." and the setting for its Virtual VMU
state, the same words whether or not the reader-only module is installed, no reader-only route and no saved
record. Every other launch must answer exactly as before: result, route, both messages, saved record.

Host decisions only. Nothing here ran on a console.
