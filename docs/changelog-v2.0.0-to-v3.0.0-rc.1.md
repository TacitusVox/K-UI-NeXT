# K-UI 3.0 RC1 changelog

**From 2.0.0 Tyrfing to 3.0 RC1 · November 22, 2026**

RC1 brings native games, Windows CE and Sega Smash Pack into one launcher with matching readers. It adds per-game virtual saves, a software updater, a searchable Games catalogue, downloadable media, selectable themes, and a new recovery workflow for damaged discs. The original Dreamcast GD-ROM drive stays in place.

This comparison starts at the released Tyrfing source `533e2906255d` and ends at the exact RC1 installer source `93f13e84d989`. It spans **728 commits** and **3,699 changed file paths**. Console observations below identify the game and feature that were exercised. Development diagnostics, experimental readers and unfinished compatibility work are identified where they affect what an RC1 owner can expect. [Tyrfing release](https://github.com/TacitusVox/K-UI-NeXT/releases/tag/v2.0.0) · [RC1 source](https://github.com/TacitusVox/K-UI-NeXT/tree/93f13e84d9893d149d2202c90417c3ec6b5aa940)

## Universal Loader, game compatibility and virtual memory cards

K-UI 2.0.0 already loaded native and Windows CE images, offered optional SCI CD music and included tools for backing up physical VMUs. RC1 brings the native and Windows CE work together in one Games menu, adds persistent virtual-card routes and integrates Sega Smash Pack. The full package supplies the GUI's matching readers. “Universal Loader” describes that common launcher. Each optional service still checks the game, image, storage interface and available memory before running. [2.0.0 baseline](https://github.com/TacitusVox/K-UI-NeXT/blob/533e2906255deb2aa1c58f77744c0de2be648936/docs/release-v2.0-notes.md) · [RC1 component inventory](https://github.com/TacitusVox/K-UI-NeXT/blob/93f13e84d9893d149d2202c90417c3ec6b5aa940/docs/distribution-maintenance.md)

### Native Dreamcast games, image loading and GD Play

- **Larger fragmented images.** The menu can describe up to 160 tracks and file extents combined for the native Background route. A Bangai-O GDI used 148 entries on the test card, enough to explain an older 64-entry launch refusal. A separate 128-entry standalone New reader serves eligible VMU-Off launches when the compact reader's memory reservation overlaps the game's SDK pool. Eligibility and map limits still depend on the installed module. Structural checks recognize more Katana SDK interrupt, allocator and controller layouts. RC1 pairs the GUI with the original Standard VMU reader `9e3295bcfaec`, compact A2 reader `f8807cb16561` and 128-slot standalone reader `e5af01888606`. These changes carry no blanket speed claim. Power Stone 2 has a physical-disc SCI virtual save/reload report. Time Stalkers' image boot was confirmed while its physical-disc startup remained a separate issue. ### Virtual cards and save compatibility

- **Persistent game saves on SD.** The native SCI paths can present a virtual card in an admitted Maple slot, retain its identity and journal writes across restarts. A1 supports games that only ask for the first slot. A2 remains available for games using the second slot. The opposite slot stays physical on the compact reader. Save sets can be assigned to game cards so progress from different games or playthroughs can be kept separately. [A1 and A2 behavior](https://github.com/TacitusVox/K-UI-NeXT/blob/93f13e84d9893d149d2202c90417c3ec6b5aa940/docs/native-virtual-a1.md) · [Native game-card evidence](https://github.com/TacitusVox/K-UI-NeXT/blob/93f13e84d9893d149d2202c90417c3ec6b5aa940/docs/universal-vmu-review-2026-11-01.md)
- **Bring existing saves onto virtual cards.** VMU Manager can copy one save or all admitted saves from a physical VMU to a fresh 200-block virtual card, browse stored cards and extract saves back into SD backup bundles. Whole-card logical import keeps companion files together and rechecks the source data. Physical copy/delete also received corrections for mini-game allocation and directory updates. [Virtual-card collection](https://github.com/TacitusVox/K-UI-NeXT/blob/93f13e84d9893d149d2202c90417c3ec6b5aa940/docs/vmu-manager-collection-test.md) · [Physical VMU corrections](https://github.com/TacitusVox/K-UI-NeXT/blob/93f13e84d9893d149d2202c90417c3ec6b5aa940/docs/vmu-manager-review.md)

Silver's dedicated SCI Standard adapter survived power-off, as did the reported Rayman 2 and Code: Veronica saves. The Code: Veronica run reached Disc 2. ### Sega Smash Pack

RC1 includes the accepted `cc81e63ca4d2` collection. Its four stages cover the outer menu, native/Genesis selections, Sega Swirl and Virtua Cop 2. All four are embedded in the GUI and supplied on the card, along with two separate 48 KiB VMU helpers. The integration preserves the original Genesis options, the original save procedure for Phantasy Star II and Shining Force, and return to the collection across native and WinCE games. Corrupt SCI blocks are isolated and retried at the same sector. The hardware acceptance sequence in one uninterrupted session was **Virtua Cop 2 → Shining Force → Phantasy Star II → Sega Swirl → Virtua Cop 2 → all other games → Virtua Cop 2**. Virtua Cop 2's long load remains. Its collection route is separate from the Japanese standalone WinCE disc. ## Games library, shell and disc tools

### Games library and launch choices

- Games saves its catalogue to the SD card. After the initial scan it can open the list without walking every game folder, show titles before artwork finishes loading, and keep the current rows visible while it fetches another page. **Scan for changes** finds additions, removals and moves. **Rebuild library** starts fresh. A canceled replacement scan keeps the last complete catalogue. Moving scan workspaces off the storage thread’s stack also fixes a reported console reset during scanning. [Catalogue](https://github.com/TacitusVox/K-UI-NeXT/blob/93f13e84d989/docs/games-catalogue-test.md) · [Scan fix](https://github.com/TacitusVox/K-UI-NeXT/blob/93f13e84d989/docs/games-scan-stack-fix.md)
- Multi-disc sets get one library entry with a disc chooser and separate launch settings for each disc. Capture folders such as `Shenmue`, `Shenmue (2)` and `Shenmue (3)` can group after a scan checks the actual disc numbers and release identifiers. Duplicate discs and incompatible releases stay separate. The existing original/2048 image chooser still works inside the disc list. [Disc grouping](https://github.com/TacitusVox/K-UI-NeXT/blob/93f13e84d989/docs/games-capture-disc-grouping.md)
- Press **X** to star a game and **Y** to cycle **All games**, **Favorites** and **Recently played**. A disc set gets one star and one recent position. Recent records a prepared launch as K-UI hands off. Search titles and aliases, filter by region or disc, jump to a letter, or give a game a display name and custom cover without renaming files. Optional full-image identity verification can reconnect activity and launch choices after a move. **Flow** adds a continuously scrolling list with a large selected cover. Switching among List, Compact, Gallery and Flow keeps the tab and selection. List and tile views continue across pages, Compact and Gallery show artwork on every loaded tile, and L/R steps between initial letters. [Library controls](https://github.com/TacitusVox/K-UI-NeXT/blob/93f13e84d989/docs/games-favorites-recent.md) · [Flow](https://github.com/TacitusVox/K-UI-NeXT/blob/93f13e84d989/docs/games-flow.md) · [Cover tiles](https://github.com/TacitusVox/K-UI-NeXT/commit/d6e73f0) · [Letter controls](https://github.com/TacitusVox/K-UI-NeXT/commit/e562f58)

### Box art, manuals and gameplay previews

- **Games → START → Scan from internet** downloads media directly over HTTPS for one game or the whole library. Covers and manuals are enabled initially, and video previews are optional. Scans reuse completed downloads after a stop. The art catalogue covers 1,104 releases, including 329 with a small JPEG option for slower connections. Downloaded art is saved at three sizes. A manually assigned or loose custom cover keeps priority. [Game media](https://github.com/TacitusVox/K-UI-NeXT/blob/93f13e84d989/docs/game-media.md)
- Downloaded page books open offline with page turns, zoom and pan. Where only a PDF is available it is saved for reading on another device. The index links 384 distinct page sets and 281 different gameplay clips across 447 regional release names. Cached previews play once after three seconds on a title in any layout and stop as soon as you move away. Clips can include up to ten seconds of 160 × 120 video with mono sound. A missing regional preview can fall back to a US or PAL clip of the same game. Books and artwork retain the matched edition. [Manuals and previews](https://github.com/TacitusVox/K-UI-NeXT/blob/93f13e84d989/docs/internet-manuals-previews.md)

## Updating from 2.0.0 Tyrfing

The October 16 Tyrfing release used an SD installation ZIP. Its Network app could update the Wi-Fi adapter firmware. RC1 adds a software updater for K-UI itself, with a local package browser, separate release and nightly channels, and a direct restart into the selected software. A stock Tyrfing card can go straight to RC1 with one SD folder merge. [Tyrfing release](https://github.com/TacitusVox/K-UI-NeXT/releases/tag/v2.0.0) · [RC1 installation guide](https://github.com/TacitusVox/K-UI-NeXT/blob/93f13e84d989/docs/release-v3.0.0.md)

### How an update preserves the card

RC1 uses updater engine 3 and version 2 of the KUP format. A full package supplies its GUI and all of its managed software. Each file retains its original component ID. There is no requirement to install the intervening nightlies in sequence. An omitted managed reader stays unavailable in that selected version, even if a copy still exists in the physical installation. Partial developer packages remain supported and retain the active versions of the software they omit. Games, virtual cards, saves, preferences, personal themes and generated launch settings stay outside the managed set. Engine 3 also corrects a previous classification error that could hide saved settings and VMU session data after a full install. [Package and file-ownership rules](https://github.com/TacitusVox/K-UI-NeXT/blob/93f13e84d989/docs/updater.md#software-ownership-and-user-data)

The installer checks the package, writes its data to a separate directory, rereads the files and records the verified selection. A complete reinstall can recover from damaged prior managed software. Direct restart validates the selected GUI before transferring control. Host tests exercise FAT32 and exFAT, cancels, interrupted writes, corrupt files, switching between versions, and restoration of a previous selection. These are checks of the installation path. Per-game Dreamcast results are recorded separately. [Installer implementation and tests](https://github.com/TacitusVox/K-UI-NeXT/blob/93f13e84d989/docs/updater.md#confirmed-failures-and-revision3)

**Final updater repair.** An early RC review could stop on the existing WinCE installation while comparing installed files. The repaired GUI completes mandatory bank and space checks before the optional comparison, preserves a verified plan if the comparison alone fails, and rechecks the package and selected card at install time. A required storage failure stops the install with the operation, filesystem result and path. Reopen the full KUP after **Restart K-UI** to confirm **Already installed** and zero files to change. ## Bootloader v3 and startup

Bootloader v3 has its own version and can start compatible future K-UI software from the card. Users with a working independent K-UI boot disc can keep it. For a new disc, the RC1 SD ZIP includes the redundant CDI from `0e4ab5a`, the build the owner confirmed booted on a Dreamcast. Its small first-stage loader reads the bootstrap from three copies separated across the disc. It checks each 32 KiB chunk by CRC, tries another copy on failure and retries damaged sectors. The first stage and the disc structures the BIOS reads still have to be readable. [Boot design and console evidence](https://github.com/TacitusVox/K-UI-NeXT/blob/93f13e84d989/docs/boot-disc-v3.md) · [Included CDI identity](https://github.com/TacitusVox/K-UI-NeXT/blob/93f13e84d989/resources/boot-disc/README.md)

The boot screen uses release-independent artwork and a countdown. The bootstrap skips its old fixed 250 ms delay once the runtime is ready. Normal cold startup goes directly to the physical SD installation and retains the splash and chime sequence. An explicit **Restart K-UI** uses the checked handoff into the selected version. The loader’s damaged-disc recovery was exercised in host fault-injection tests and Flycast. No fresh timing comparison on a physical Dreamcast is claimed for the complete RC1. [Disc verification](https://github.com/TacitusVox/K-UI-NeXT/blob/93f13e84d989/docs/boot-disc-v3.md#verification) · [Cold-start path](https://github.com/TacitusVox/K-UI-NeXT/blob/93f13e84d989/docs/root-boot-restoration.md)
