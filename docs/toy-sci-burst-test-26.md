# Toy Commander test 26

The 60 Hz intro takes the original game's lag exit after its video decoder falls behind the audio clock. The movie's GDFS poll asks for one nonblocking progress pass. On the native SCI reader, EXEC and CHECK can spend that pass waiting for card data. Earlier tests also verified good game-destination bytes at the cutoff and found that a second large RAM reservation prevented the game from allocating its resources.

Test 26 uses bounded multi-block SCI DMA for the movie payload. It admits the original raw Toy Commander route and uses the existing 284 KiB compact Background lease. It assigns one additional page to auxiliary code and retains 172 KiB of checked cache plus 16 KiB reserved for staging. The opening read and requests outside the admitted movie range retain the ordinary reader. After the opening read, a request can consume verified blocks while an unrelated future DMA is in flight. A pending burst can return control to the movie code. The SD card data passes a checked prefix through the existing retail cursor and GD completion path.

The starting source is the preserved test-suite reader at `8f64f91b4482`, on Main-derived source `f08714c`. This test is a distinct selectable module. Its result should be compared to the earlier raw controls using the same card, image, and display mode. The wire transport proposal comes from the prior October CMD18 capture, where one receive DMA delivered 31 complete checked blocks on the console. The earlier capture ran in a diagnostic rather than during a game.

Use Card Tools to select the original Toy Commander GDI and open Options, Advanced, Tests. Run test 26 with its default settings. Let the two opening movies run. After the intro finishes or returns to the menu, hold both triggers and A+B+X+Y for about three seconds. After REPORT SAVED TO SD appears, release the buttons and press Start to reboot to the K-UI CD. The report is written to `/reports/toy/26.txt` or its next unused numbered suffix.

The report uses hex values and the existing 781250 Hz timer. GD and SCI time cover visits attributed to post-opening movie requests. The TICK row measures controller service during the intro producer epoch and has a different time scope. `ARM` counts bursts armed, `CHECKED` counts verified physical blocks published, `CUT` counts short or rejected bursts, and `FALLBACK` counts requests switched to the ordinary reader after a burst stall. `REQUEST` and `FIRST` count movie requests and requests whose first block was ready. `READY` counts fully cached requests that end inside the current movie extent. `LEAD` is the maximum ready lead in 512-byte blocks. `WIRE` counts received bytes before framing and verification.
